# STANDES

3D-конфигуратор модульных стеллажей: собираешь стеллаж по ячейкам, расставляешь несколько
штук по комнате — они примагничиваются друг к другу гранями и углами, — и сразу получаешь
спецификацию, карту раскроя и цену.

```bash
npm install
```

## Две версии — два отдельных сайта

Языка-переключателя внутри приложения НЕТ и не должно быть: русская и английская
версии собираются отдельно и живут на разных адресах.

| | Язык | Валюта | Разработка | Сборка |
|---|---|---|---|---|
| Русская | RU | ₽ | `npm run dev` → **:5173** | `npm run build` → `dist/` |
| Английская | EN | $ | `npm run dev:en` → **:5174** | `npm run build:en` → `dist-en/` |

`npm run build:all` собирает обе сразу.

Если открыли `:5173` и видите рубли — это нормально, это русская версия.
Английская на `:5174`.

Валюту можно развязать с языком: `VITE_CURRENCY=USD npm run build` даст
русский интерфейс с долларами.

## Как это устроено

Единственный источник правды о размерах — `src/domain/frame.ts`. И разбор стеллажа на детали,
и магниты, и инспектор, и превью в библиотеке считают положение ячеек по одним и тем же
функциям, поэтому разойтись не могут.

```
src/domain/
  types.ts       модель, единицы, система координат   ← контракт, менять осторожно
  frame.ts       размерная математика каркаса          ← сюда смотрят все остальные
  geometry.ts    ShelfUnit → Part[] (то, что рисуется и попадает в смету)
  snapping.ts    магниты: анкеры, решатель, применение
  collision.ts   SAT для повёрнутых пятен застройки
  bom.ts         спецификация, фурнитура, вес, цена
  cutlist.ts     раскрой по листам (MaxRects + гильотина)
  materials.ts   каталог: цвет, плотность, цена, доступные толщины, размер листа
  edit.ts        операции редактирования (колонки, ряды, ячейки, объединения)

src/three/       сцена: рендер деталей, свет, постобработка, драг, комната, план
src/ui/          интерфейс; src/ui/controls — дизайн-система
src/export/      JSON, ссылка, CSV, GLB, PNG, печатная спецификация
src/store/       zustand + immer + zundo (история)
```

**Единицы.** Вся доменная модель — в миллиметрах. Сцена Three.js — в метрах. Перевод только
на границе рендера, через `mm()` из `types.ts`. Смешивать нельзя.

**Оси стеллажа.** Origin — центр пятна застройки на полу. `+X` вправо, `+Y` вверх,
`+Z` вперёд к зрителю. Значит задняя плоскость на `z = -depth/2`, фасады накладные и
сидят на `z = +depth/2`.

**Ряды считаются снизу.** `rows[0]` — нижний ряд. В инспекторе список показан сверху вниз,
но индексы хранятся правильные.

## Решения, которые стоит знать

**Драг живёт вне истории.** Во время перетаскивания позиции пишутся в `drag.live`, а не в
проект, и коммитятся один раз на `pointerup`. Поэтому одно перетаскивание — одна запись undo,
а не сто, и BOM не пересчитывается на каждом кадре.

**Толщину можно только уменьшать.** `buildableThickness` в `geometry.ts` приводит толщину
листовой детали к ближайшей каталожной, но исключительно вниз — так деталь физически не может
вылезти из своего гнезда, а раскрой состоит из листов, которые реально продают. Именно поэтому
стеклянная полка в гнезде под 18 мм становится 10 мм.

**Короб ящика всегда из фанеры**, независимо от материала фасада: никто не собирает выдвижной
ящик из дуба под дубовым же фасадом.

**Магниты.** `solveSnap` перебирает кандидатов четырёх типов — грань-в-грань, угол-в-угол,
к стене, по сетке — и берёт минимальную цену. Цена — это расстояние от курсора плюс штрафы за
доворот и за тип. Совпадение высоты и глубины даёт бонус, поэтому «родные» стыковки липнут
заметно охотнее. `Alt` временно выключает привязки.

**Изоляция сбоев.** Каждая панель обёрнута в `ErrorBoundary`: падение инспектора или сцены
не уносит приложение целиком.

## Горячие клавиши

Полный список — по `H` внутри приложения. Основное: `1/2/3` — вид, `M` — магниты, `G` — сетка,
`R` — поворот на 90°, `Ctrl+D` — дублировать, `Ctrl+Z` / `Ctrl+Shift+Z` — история,
`B` — смета, `F` — фокус на выборе, стрелки — сдвиг по сетке.

## Что осталось за бортом

- Раскрой не учитывает направление волокон по умолчанию (тумблер есть, но проверять
  результат на реальном заказе стоит вручную).
- **Цены — заглушки, их надо подставить свои.** Рублёвый и долларовый прайсы
  НЕЗАВИСИМЫ: `pricePerM2: { rub, usd }` в `materials.ts`, фурнитура — в `bom.ts`.
  Курса в коде нет вообще. Долларовые значения выведены из рублёвых один раз
  при разделении прайсов и дальше живут своей жизнью — проставьте под экспортный
  рынок свои.
- Экспорт спецификации — печатная HTML-страница (`Ctrl+P` → «Сохранить как PDF»),
  а не готовый PDF: библиотеки генерации PDF в проекте нет.
